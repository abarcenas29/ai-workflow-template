### Request
A centralized file to control which model each orchestrator agent uses, instead of putting `model` in each agent file. Must be deployable to projects consuming this template package. Default for now: DeepSeek Flash (`deepseek/deepseek-flash`) for all agents.

### Key research findings (verified against OpenCode V2 docs)
- OpenCode V2 reads config ONLY from `opencode.json(c)` files (auto-discovered: root `opencode.json`, and `.opencode/opencode.json(c)`) and Markdown agent files. No `extends`/`include` for arbitrary JSON files.
- Per-agent model is set via the `agents.<id>.model` map in config (string `provider/model[#variant]` or expanded object). Markdown agents merge with config `agents` entries by ID.
- Precedence: every discovered `.opencode` config OVERRIDES every direct config. So `.opencode/opencode.json` merges over root `opencode.json`.
- Subagent with no configured model inherits parent session model (the problem being solved).
- DeepSeek provider models (models.dev): `deepseek-flash`, `deepseek-v4-flash`, `deepseek-v4-pro`, `deepseek-v4-flash-vision-exp`. User asked for "deepseek flash" -> `deepseek/deepseek-flash`.
- Sync engine facts (scripts/sync.js): `opencode.json` is project-owned (never copied/overwritten/pruned; scaffolded create-if-absent from `opencode.mcp.example.json`). `.opencode/**` files sync via the `__opencode__` channel, EXCEPT `openCodeExcluded` (node_modules, package.json, package-lock.json, bun.lock, .gitignore). `.opencode/opencode.json` currently exists (schema only) and is already synced/manifest-tracked.

### Design decision (user chose "managed file + example wiring")
Native, sync-safe mechanism that honors the intent: put the central model map in `.opencode/opencode.json` (auto-discovered, `__opencode__`-synced, merges OVER the project-owned root `opencode.json`). Also add the `agents` model map to `opencode.mcp.example.json` so fresh consumers scaffolding `opencode.json` get models too. Rationale: a standalone `.opencode/agents-models.json` would be inert (OpenCode does not load arbitrary JSON), so `.opencode/opencode.json` is the correct carrier. Consumers keep their root `opencode.json` untouched; the `.opencode/opencode.json` file is the centrally-managed, sync-updated one.
